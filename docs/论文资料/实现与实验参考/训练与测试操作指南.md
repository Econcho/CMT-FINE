# CMTDet：环境、数据、训练、恢复与测试

> 当前正式骨干已切换为HGNetV2-B0，请用[新骨干训练指南](HGNetV2-B0骨干与训练指南.md)中的配置和预训练命令。本页的数据、日志、恢复与测试机制仍适用；下面旧ConvNeXt配置的示例保留作历史复现。

## 1. 当前软件的使用范围

项目根目录是 `F:\antiuav\TSCRNet\CMTDet-main`。所有下述相对路径均从项目根目录执行。

代码提供：CMT、CMTDet、COCO 数据读取、DUT 转换、可配置训练、实时进度、每批次／每轮日志、last/best 完整 checkpoint、恢复训练、COCO 与原框面积 `<100` 指标。没有运行正式全量收敛实验，不提供未经验证的最佳超参数。

`configs/cmtdet_b.yaml` 是高容量研究配置；`cmtdet_dev.yaml` 是开发配置；`smoke.yaml` 只验证程序，不用于比较模型精度。B 版不承诺能在 16 GB 显存下用 1024 输入和任意 batch 训练。降低 microbatch、增加累积、开启 encoder checkpointing 可以节省部分显存，但不能替代实际资源测量。

## 3. 默认 COCO 数据格式

每个 split 的 JSON 包含 `images/annotations/categories`；每条框为 `bbox=[x,y,w,h]`，原图连续边缘坐标，宽高必须为正。`category_id` 不需要从 0 连续编号，程序会建立连续内部标签并在测试时映射回原 ID。

`data.yaml` 示例：

```yaml
root: /data/coco
train:
  images: train2017
  annotations: annotations/instances_train2017.json
val:
  images: val2017
  annotations: annotations/instances_val2017.json
test:
  images: test_images
  annotations: annotations/test_annotations.json
```

`root` 相对 YAML 所在目录解释；没有 root 时就是 YAML 所在目录。每个 images/annotations 可以使用绝对路径。没有 test 标注就省略 test，使用 `--split val` 评估；程序不会自动构造测试集。

真实 COCO 的无标注 test 集不能在本机计算 AP。训练使用 train，训练中验证使用 val，最终测试 split 由命令指定。

其他约定：

- 图片读取为 RGB，尺寸必须与 JSON 一致；不静默修复 ID、类别或退化框。
- `iscrowd` 和 `ignore=true` 的框不作为普通正样本；训练热图排除其区域，类别背景监督排除明显覆盖 ignored 框的候选；评测时 ignore 映射为 COCO crowd。
- 不接受 `.pt` 数据集；模型和数据适配相互独立。
- `model.classes` 必须与 categories 数量一致；多类别例如 `--set model.classes=80`。
- 输入保持纵横比缩放，右／下填充为 114，之后 ImageNet RGB 标准化；GT 同步变换。保存每张图实际 sx/sy，考虑 resize 四舍五入。
- 当前只实现水平翻转增强，未默认叠加 Mosaic、颜色扰动或多尺度训练。需要扩展增强时统一放在数据层并同步更新 bbox 与几何元信息。

## 4. DUT 转换

本机 DUT 原始目录为 `F:\antiuav\dataset\DUT`，各 split 含 `img/` 和 `xml/`。转换只写新的 COCO JSON/YAML，默认不复制和不修改原始图片。

PowerShell 7：

```powershell
& '.\.venv\Scripts\python.exe' -m cmtdet convert-dut --source 'F:\antiuav\dataset\DUT' --output data/dut_coco
```

Linux：

```bash
python -m cmtdet convert-dut --source /data/dataset/DUT --output data/dut_coco
```

可选参数：

| 参数 | 含义 |
|---|---|
| `--splits train val test` | 实际转换哪些 split |
| `--limit-images 8` | 每个 split 只转换前8张，用于 smoke，0 表示全部 |
| `--coordinates inclusive` | 默认：零基 inclusive，xmax/ymax 加1；与现有 BCRNet DUT 转换口径一致 |
| `--coordinates voc1_inclusive` | 一基 VOC inclusive，xmin/ymin 减1 |
| `--coordinates half_open` | 框已是半开坐标，不做 ±1 |

不能因为同为 XML 就假定某种坐标约定。正式实验应根据数据来源确认并固定。转换元信息和 `conversion.json` 保存所选约定与 subset limit。

输出目录已有 `data.yaml` 时拒绝覆盖。若把转换结果带到另一台机器，原始图片引用路径必须更新；也可在目标机器重新转换原始 DUT。

## 5. 先运行小样本检查

```bash
python -m cmtdet convert-dut --source /data/dataset/DUT --output data/dut_smoke --limit-images 8
python -m cmtdet train --config configs/smoke.yaml --data data/dut_smoke/data.yaml --output runs/smoke --device cuda --stop-after-epochs 1
```

`stop-after-epochs=1` 在一轮完整 epoch 后停止，配置中总训练日程仍保留，因此可以验证恢复。

另外：`--limit-images N` 限制加载的图像数；`--max-batches N` 仅限制每轮训练 batch 数。`test --max-batches` 限制测试 batch 数。任何子集结果都标记为部分验证，不作为整套 DUT 正式结果。

CPU 可以运行 smoke，但大配置较慢。正式训练不要沿用 limit/max-batches，也不要将 smoke checkpoint 当作预训练模型。

## 6. 正式训练和参数自定义

开发模型：

```bash
python -m cmtdet train --config configs/cmtdet_dev.yaml --data data/dut_coco/data.yaml --output runs/dut_dev --device cuda --set train.epochs=100 --set train.batch_size=2 --set train.accumulation=4 --set train.workers=4
```

B 版结构：

```bash
python -m cmtdet train --config configs/cmtdet_b.yaml --data data/dut_coco/data.yaml --output runs/dut_b --device cuda --set train.batch_size=1 --set train.accumulation=16 --set train.val_interval=1
```

以上代码可以从随机初始化训练。若使用 ConvNeXt 作者的预训练 checkpoint，加：

```bash
--pretrained-backbone /data/weights/convnext_base_1k.pth
```

程序显式映射作者 `downsample_layers/stages` 到本实现，严格检查所有骨干参数；分类器被排除。它不自动下载权重，不自动识别任意 timm/torchvision checkpoint。形状不匹配会报错，不能静默跳过。不要在使用随机初始化的 baseline 与使用大规模预训练的新模型之间做不公平比较。

所有参数在 `src/cmtdet/config.py` 有默认值，`--set section.key=value` 可重复传入；也可以直接编辑 YAML。未知键报错，避免拼写错误后继续使用默认值。

| 常用参数 | 作用 |
|---|---|
| `model.input_size` | 输入正方形边长，必须是32倍数 |
| `model.classes` | 类别数 |
| `model.queries` | 最大检测 query 数，必须足以覆盖一张图的 GT |
| `train.epochs` | 总训练轮数 |
| `train.batch_size` | microbatch，不等于有效 batch |
| `train.accumulation` | 梯度累积批次数，有效 batch=两者乘积；当前单进程 |
| `train.lr / backbone_lr` | 新层与骨干学习率 |
| `train.weight_decay / grad_clip` | AdamW 衰减与梯度裁剪 |
| `train.warmup_epochs` | LR warmup；之后 cosine |
| `train.amp / amp_init_scale` | CUDA AMP 和初始 scale；raw moments 始终 FP32 |
| `train.workers` | DataLoader worker 数，Windows 调试从0开始 |
| `train.val_interval` | 每 N 轮 val，最后一轮总会 val |
| `train.patience` | 多少次无改善的验证后早停，0关闭；不按未验证的 epoch 计数 |
| `train.min_delta` | 最佳指标最小增量 |
| `train.monitor` | 默认 AP50_95，可选输出 metrics.json 的键 |
| `train.progress=false` | 关闭控制台进度条，仍保存全部日志 |
| `train.*_weight` | 检测／证据／质心／gate／临时框等损失权重 |
| `model.checkpoint_encoder` | 用额外重算换显存 |
| `model.denoising=0` | 关闭训练期 DN 辅助查询 |

建议仅对 AP/AR 类指标使用早停 monitor；`GT_bbox_area_lt100` 是样本数量，不应被用作模型选择指标。若选择 tiny AP 但验证集没有 tiny GT，指标为−1，程序不更新 best 和 patience，并记录警告；此时不会凭空产生合法的最佳 checkpoint。

## 7. 训练中看到什么、保存什么

每个 epoch 显示 batch 进度、当前 loss 与 LR；每轮结束输出完整 JSON 摘要。文件包括：

| 文件 | 内容 |
|---|---|
| `config.json` | 所有最终生效的配置 |
| `environment.json` | PyTorch、设备、参数、类别、数据路径和标注hash、源码hash、预训练来源 |
| `batches.jsonl` | 每个 batch 的各损失、梯度范数、LR、AMP scale、optimizer step |
| `epochs.jsonl` | 每轮平均损失、验证指标、耗时、跳过更新数、best 与耐心计数 |
| `history.csv` | 便于 Excel／绘图读取的主曲线 |
| `train.log` | 开始、epoch摘要、早停和异常 traceback |
| `last.pt` | 最后完成 epoch 的完整状态，原子写入 |
| `best.pt` | monitor 确实改善时的完整状态 |
| `status.json` | 完整结束、用户指定轮数停止、早停或异常 |
| `resume_events.jsonl` | 每次恢复时的checkpoint、epoch与当前环境 |
| `val/epoch_XXXX/` | 该轮完整验证产物 |

loss 下降不等于 AP 上升。`centroid_eligible` 是直接质心监督符合条件的数量；如果始终为0，需要查看证据质量、窗口和多目标条件，不应该直接忽略这条诊断。

CUDA AMP 遇到溢出可能跳过更新，日志记录 `amp_skipped_updates`。所有 loss 非有限值会报错；不静默把 NaN 置零继续训练。

当前每个 epoch 只保存 last/best，不默认保留每轮完整模型以避免大量磁盘占用；验证结果仍逐轮保存。大数据集每轮 raw queries／match 可能很大，可以在训练前设置 `eval.save_raw_predictions=false` 或 `eval.save_match_details=false`，配置会留档。

## 8. 恢复训练

```bash
python -m cmtdet train --resume runs/dut_b/last.pt --data data/dut_coco/data.yaml --output runs/dut_b --device cuda
```

checkpoint 包含模型、optimizer、scheduler、scaler、epoch、step、best、patience、Python/NumPy/Torch/CUDA RNG、DataLoader generator、配置与标注hash。恢复时不要再次传 `--config`、`--set` 或 `--pretrained-backbone`。

恢复会核验配置、标注指纹和 smoke limit。原本使用 limit/max-batches 的验证运行，恢复时必须传相同参数；不能把部分数据训练的状态当作完整实验继续。

支持按 epoch 边界恢复。中途杀掉一个 epoch 会从 last 保存的上一完整 epoch 继续，该轮部分计算会重做。CUDA grid_sample 的反向可能有非确定性，因此不承诺跨GPU／跨平台逐bit一致；CPU固定环境的恢复一致性已验证。

恢复原目录时应使用最新 `last.pt`。若主动回退到旧 checkpoint，应输出到新目录，避免当前目录已有的较新日志和旧 epoch 混合。当前版本不提供修改总日程后“严格恢复”的捷径；要延长或改变训练策略应作为新的 fine-tuning 实验实现并记录。

## 9. 测试与结果解释

```bash
python -m cmtdet test --weights runs/dut_b/best.pt --data data/dut_coco/data.yaml --split test --output runs/dut_b_test --device cuda --set eval.batch_size=1 --set train.workers=4
```

COCO 标准输出：AP50:95/AP50/AP75/AP_small/AP_medium/AP_large；AR1/AR10/AR100/AR_small/AR_medium/AR_large。使用官方 pycocotools，IoU=.50:.05:.95，101个recall采样点，maxDets=[1,10,100]。

新增：

- `AP50_95_bbox_area_lt100`：原图标注 bbox 的 `w*h<100`，严格不含100。
- `AR50_95_bbox_area_lt100_maxDets100`：同一面积组、IoU阈值平均、每图每类按COCO maxDets=100。
- `GT_bbox_area_lt100`：本次评测符合定义且非ignore的GT数量。

标准 COCO 面积分组保留标注提供的 area，特殊 tiny 指标单独使用 bbox 面积。9×11=99 属于特殊组；10×10=100不属于；resize后的尺寸不影响这组归属。全部 GT 保留，其他尺寸和 ignore 框通过 COCO ignore 机制处理，不先过滤成只有 tiny 的数据集。

值范围0–1；无有效GT为−1，空预测但有GT则AP/AR为0。不能把−1当成性能为负或算法失败。

测试保存：

- `metrics.json`、`report.md`、`coco_console.txt`；
- `predictions.json`：原图坐标 COCO bbox 结果；
- `raw_queries.jsonl`：阈值／Top-K前的 query 框和 logits（可配置关闭）；
- `images.json`：每图预测数、原始尺寸与实际sx/sy；
- `coco_curves.npz`、`tiny_lt100_curves.npz`：完整precision/recall/scores张量及坐标轴；
- `coco_matches.jsonl`、`tiny_lt100_matches.jsonl`：逐图逐类各IoU匹配和ignore状态；
- `metadata.json`：指标口径、有效图像清单、部分评测标志、配置；
- `checkpoint.json`：权重路径、SHA256、epoch、split和标注SHA256。

默认不做 NMS，按集合预测输出Top-K；预测保存上限默认300，COCO评价内部仍用100。不要设置高置信度阈值后声称得到完整PR曲线；默认 `eval.score_threshold=0`。

测试目录必须为空的新目录，防止不同权重结果混在一起。

## 10. 常见问题

- **输出目录非空：** 新实验换新目录；继续训练使用 resume。
- **类别数／类别映射不符：** 修改训练配置 classes，检查 train/val/test categories；不能只在测试时更换标签表。
- **显存不足：** 先减microbatch；encoder checkpoint已可用；用dev配置验证流程。大模型正式实验可能需要更大显存，不应把降分辨率得到的结果仍标为1024。
- **tiny 指标为−1：** 查看GT_bbox_area_lt100。本次DUT前8张子集没有符合原框面积<100的GT，这是合法结果。
- **AP接近0：** 从随机初始化训练1–2轮的smoke结果预期无检测质量保证；检查训练是否充分、尺度、预训练和标注，而不是用smoke评判idea。
- **只有完整模型支持某消融吗：** 见独立[消融指南](消融实验指南.md)，结构消融要重训；测试时关闭CMT仅是依赖性干预。
